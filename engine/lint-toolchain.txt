# Rust toolchain the `lint` gate (rustfmt check + clippy -D warnings) runs on.
#
# Pinned because clippy on floating `stable` gains lints with each release, and
# under `-D warnings` a new lint that fires on existing code fails every PR
# that runs `lint` at once, for a reason unrelated to the PR (a882420, #328).
# With the pin, new lints arrive only when this line moves.
#
# Read by scripts/lint-toolchain.sh for both consumers: the CI `lint` job and
# `mise run lint`. The local gate and CI therefore run the same clippy.
# LINT_TOOLCHAIN=<toolchain> overrides the pin for the mise lint tasks. Only
# the canary below sets it.
#
# Only `lint` is pinned. The build and test jobs stay on stable, since they do
# not run with -D warnings. MSRV has its own pin (`rust-version` in
# engine/Cargo.toml and the msrv job in .github/workflows/ci.yml).
#
# When: the weekly lint canary (.github/workflows/lint-canary.yml) runs this
# gate on floating stable. While stable is ahead of the pin, it keeps an issue
# titled "lint pin is behind stable" open, marked either "behind" (with the new
# lint names) or "free bump". Either one is the cue to bump.
#
# Bump procedure (do all of this in ONE PR):
#   1. Replace the version below with the new stable X.Y.Z.
#   2. Run `mise run lint`, and fix whatever the new lints flag in the same PR.
#   3. If a fix reaches for an API newer than the MSRV, confirm it with
#      `cargo +<msrv> check --workspace --locked` (see the msrv job).
#
# Format: the first line that is a bare X.Y.Z is the pinned version.
1.98.1
